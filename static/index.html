zttp agent-compiler

Your AI writes the code. The compiler proves it.

zttp is an agent-compiler: the compiler works as a second agent in your coding session. It checks every draft before it reaches disk, and it fixes the mistakes it knows without another model call.

zttp is experimental software. It is not a supported product or a production-ready runtime/compiler. Expect bugs and breaking changes.

One write path

Every edit has two authors.

  1. 01 Draft

    The agent proposes a handler.

  2. 02 Prove

    The compiler checks it before it is saved.

  3. 03 Repair

    The compiler fixes known failures itself, with no model call.

  4. 04 Write

    Only proven code is written.

zttp records who wrote each edit: the model or the compiler. For five safety properties, the compiler plans, applies, and checks the fix on its own, and undoes it if the fix breaks something else.

Why zts restricts TypeScript

zts removes the features the compiler cannot fully check, such as classes, async, try/catch, and while loops. Each removal makes one guarantee provable and gives the agent fewer wrong ways to write code.

Compare zttp with bolt-on checkers

Agent plus checker: the code is written first and checked afterwards, in full TypeScript.

Compiler plus agent: the compiler only returns error text, and the model retries with no limit.

zttp: the compiler is an agent too. It shares the only write path with the model and writes its own repairs.

Attested runtime

Ship the proof with the handler.

zttp deploy builds one signed binary. Before it serves a request, the binary checks the proof again with its own independent checker, and it refuses to start if anything inside was changed. Anyone can run zttp verify <url> to check the signature. Pinning a key with --trust-key authenticates the signer.

What changed in 0.26.0

fetchWithRetry now refuses a write that carries a credential header, so a write with the user's authority does not repeat. The changelog gives the migration.

The expert tools now read the same analysis as zttp check, and every rejection that they report carries a repair plan. Thirteen error codes that had no help text now have it.

The acceptance kernel now checks results_checked again itself: every read of a Result must be guarded. zttp proofs verify names the properties that the kernel checked on a Checked: line.

A flow property is now unproven until its pass proves it. A certificate no longer claims capability_bounded for a handler without Effects<...>. A Result that a loop body reassigns is no longer proved checked on the next iteration.

zttp proofs verify refuses a bundle whose certificate or contract differs from the copy inside the binary. A module export runs with only the capabilities that it declares. The JWT and webhook helpers refuse an empty secret.
